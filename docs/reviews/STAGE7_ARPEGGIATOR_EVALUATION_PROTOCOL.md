# Stage 7 Arpeggiator baseline evaluation protocol

## Authority and status

Protocol identity: `nightdrive.stage7-arpeggiator-evaluation.v1`.

This documentation-only checkpoint freezes the product-owner-approved 28-fixture baseline design and listening procedure and is accepted and merged through PR #103. The identity versions this matrix, its pre-output sampling rules, audition controls, two listening passes, presentation order, and interpretation rules. It is separate from the genre-profile data, Arpeggiator policy, component-seed derivation, PRNG, and MIDI IR versions. No fixture, MIDI/audio artifact, rating, or listening result exists because of this checkpoint.

The four fixed Harmony source contexts and replay versions are owned by [Stage 7 Arpeggiator golden-case source records](STAGE7_ARPEGGIATOR_GOLDEN_CASES.md). The [audition-artifact contract](STAGE7_ARPEGGIATOR_AUDITION_ARTIFACT.md) owns MIDI transport and mapping. This protocol changes neither source context nor deterministic generation behavior.

Use each of these golden cases, in the listed canonical matrix order, with its already-frozen Harmony template, tonic, scale, inclusive Arp range, and version identities:

|---|---|

For **each** case, use exactly these seven conditions in the listed canonical matrix order:

| Panel | Energy | Complexity | Root seed |
|---|---|---|---:|
| Primary baseline | `medium` | `medium` | `0` |
| Primary Energy low endpoint | `very-low` | `medium` | `0` |
| Primary Energy high endpoint | `very-high` | `medium` | `0` |
| Primary Complexity low endpoint | `medium` | `very-low` | `0` |
| Primary Complexity high endpoint | `medium` | `very-high` | `0` |
| Seed variation | `medium` | `medium` | `1` |
| Seed variation | `medium` | `medium` | `2` |

The primary matrix contains four cases times five conditions, or **20 fixtures**. The seed panel adds two fixtures per case, or **8 fixtures**; its seed-`0` baseline is already counted in the primary matrix. The closed initial baseline therefore contains **28 distinct fixtures**, each included exactly once. Seeds `0`, `1`, and `2` are valid canonical uint32 roots.

Energy and Complexity vary one dimension at a time while the other stays `medium`. The `very-low` and `very-high` endpoints expose the strongest accepted directional behavior in this initial baseline. The full `5 × 5` Cartesian product is not used because this study seeks interpretable directional evidence rather than exhaustive enumeration. Additional seeds `1` and `2` were selected in numeric order before any output or listening inspection. Seed searching and cherry-picking are prohibited.

## Fixture identity and evidence fields

Each fixture has a stable internal source key formed from the exact tuple `goldenCaseId__energy__complexity__seed-N`, where `N` is the decimal root seed. For example, `dark-synthwave-chorus-001__medium__medium__seed-0` identifies the first matrix condition before presentation randomization. This is an evaluation record key, not a musical output, hash, file path, or blind label.

Each future fixture record must retain the exact golden-case ID, profile ID, Energy, Complexity, root seed, profile-data version, Arpeggiator policy version, component-seed-derivation version, PRNG version, and this evaluation-protocol version. Its opaque presentation ID is assigned separately and recorded in a concealed mapping. The four replay versions are the exact identities in the frozen golden-case source records; no alternate versions are selected here. Later artifact and result records may add their own hashes and observations without changing this source identity. No event/result or MIDI hash is generated by this checkpoint.

## Deterministic blind presentation

The presentation-order seed is `0`. It is evaluation-only and is not a musical root seed, component seed, Stage 7 generation PRNG input, or canonical composition state.

Later preparation tooling must form the 28-element source list in the case and condition order above, then apply one descending Fisher–Yates shuffle. Start an **independent presentation-only** `nightdrive.prng.mulberry32.v1` stream at seed `0`. For each index `i` from `27` down to `1`, consume one uint32 output, set `j = output % (i + 1)`, and swap elements `i` and `j`. Assign `ND7-001` through `ND7-028` in final presentation order, with three-digit zero padding. This fixes the deterministic ordering mechanism without implementing or executing it here; it does not alter Stage 7 policy selection. The mapping must be checked for one appearance of every source key, frozen before listening, hidden through Pass 1, and retained with the order in evaluation evidence. Do not manually reorder after inspecting or hearing outputs.

## Audition controls and remaining setup gate

The existing audition-artifact contract fixes 960 PPQ, 4/4, eight bars ending at tick `30720`, 120 BPM (`500000` microseconds per quarter), Chords and Arp note-on velocities `100`, and exactly conductor/Chords/Arp tracks. Bass, Lead, program changes, and embedded instrument/effect state are absent. This protocol does not redefine those MIDI controls.

For manual FL Studio listening, use the exact product-owner-recorded states in the [FL Studio listening-setup reproducibility checkpoint](STAGE7_ARPEGGIATOR_LISTENING_SETUP.md): FL Keys for Chords and 3xOsc for Arp, with the same respective states for all 28 fixtures. The checkpoint records the installed identities, factory presets, import/routing setup, mixer baseline, and external template save/reopen evidence. The Stage 5 interoperability record proves only its declared import environment, not these Stage 7 instrument states.

Use no effects, inserts, sends, or automation. Set the Chords fader, Arp fader, and master to `0 dB`. If clipping requires a master reduction, document one global reduction and apply it unchanged to all fixtures before rating; a change after ratings begin requires a consistent restart. Keep playback volume fixed during a review session.

## Pass 1 — blind individual review

Present each fixture under only its opaque `ND7-###` label. Until every Pass 1 response is locked, conceal profile, golden-case ID, Energy, Complexity, root seed, and the label-to-fixture mapping. Avoid rapid A/B comparison in this pass. Give one uninterrupted first listen where practical and allow one replay before finalizing the rating.

For **every** fixture, each reviewer records the existing six `1–5` ratings: Harmonic coherence, Rhythmic appropriateness, Motif consistency, Register/arrangement, Section/genre alignment, and Musical usefulness. Also record the existing anchor, “Would a producer actually use or develop this material?” with exactly `yes`, `maybe`, or `no`; a short evidence/comment field; and any severe issue observed. Preserve each reviewer’s individual response.

## Pass 2 — revealed controlled comparisons

Only after all Pass 1 ratings are locked, reveal grouped comparisons within each golden case. Use the seed-`0`, `medium`/`medium` fixture as the common baseline for all three panels.

| Panel | Ordered conditions within one golden case | Question | Responses |
|---|---|---|---|
| Energy | `very-low`/`medium`/seed `0`; `medium`/`medium`/seed `0`; `very-high`/`medium`/seed `0` | Does increasing Energy produce an intuitive musical progression? | `clearly yes`; `somewhat`; `unclear`; `counterintuitive` |
| Complexity | `medium`/`very-low`/seed `0`; `medium`/`medium`/seed `0`; `medium`/`very-high`/seed `0` | Does increasing Complexity add useful musical interest without simply creating noise or instability? | `clearly yes`; `somewhat`; `unclear`; `counterintuitive` |
| Seed | `medium`/`medium` with root seeds `0`, `1`, `2` | Do these feel like variations of the same profile rather than unrelated behaviors? | `clearly same profile`; `mostly same`; `mixed`; `materially inconsistent` |

Require a short explanation for every panel response. These categories are diagnostic baseline evidence, not acceptance thresholds.

## Session procedure and interpretation

Use one consistent playback environment per review session. Keep FL Studio settings, instruments, mixer, effects, and playback volume unchanged during that session. Take a short break approximately halfway through the 28-fixture Pass 1 set. Record reviewer expertise/context and playback environment; collect consent and only necessary metadata. Do not require a particular headphone model, interface, or room. Preserve individual responses and disagreement rather than averaging them away.

Within one golden case, Harmony context is fixed, so Energy, Complexity, and seed comparisons can be interpreted as within-profile Stage 7 behavior comparisons. Across the four cases, Harmony contexts intentionally differ. Reviewers may assess whether the **complete profile experiences** are meaningfully distinguishable, but must not claim that cross-profile differences are caused solely by Arpeggiator policy.

The first baseline records per-fixture ratings, anchor responses, comments, and severe issues; within-profile Energy direction, Complexity direction, and seed stability; and perceived distinguishability across complete profile experiences. There is **no numeric pass threshold** at this stage. Poor results may prompt investigation of a deterministic defect, profile-policy weighting, Harmony/Arp interaction, isolated seed sensitivity, audition/timbre confounds, or a profile hypothesis requiring a future immutable profile-data version. Do not pre-classify an output or silently revise accepted V1 data. Exact numeric thresholds require baseline evidence and a later decision.
